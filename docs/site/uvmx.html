UVMX

用 Python 写用例，仍由 UVM 运行。

不另造一套 scheduler 或 factory。把 Python 用例接入现有 UVM 环境，保留 SV driver、monitor 与时序，让验证意图和事务逻辑留在 Python。

04

Python 方法同步执行，时间仍归 SV

当前只接入下面五个 phase。Python 方法均为普通实例方法，只接收 self。

FUNCTION CONTEXT

build_phase(self)

先调用 SV 基类 build_phase，再同步进入 Python build_phase。可创建 Python 状态、完成配置；不能延时或调用阻塞原语。

SV super.build_phase↓Python build_phase↓返回 UVM

run_phase 中可以使用 svx.delay() 等同步原语，由 SV 调度推进仿真；不使用 async / await。当前 bridge 顺序调用 super.run_phase()，随后为 Python 回调 raise / drop objection。

05

新增 Python 用例，不新增 SV 用例类

只要继续使用已编译的 SV 基类与既有可见契约，就可以保持同一份仿真可执行文件。

首次构建 · 固定接入能力
  1. 编译原有环境、UVMX 包和 Test bridge
  2. 生成所选自定义 SV 基类的注册代码
  3. 构建 / 加载 SVX native 运行库
之后保留 executable / native 库 / 生成 SV
后续迭代 · 仅新增 Python 声明
from uvmx import Test, uvm_test

@uvm_test(
    canonical_id="py://verification/NewTest",
    factory_name="new_python_test",
)
class NewTest(Test):
    def run_phase(self):
        # Python 场景、事务与检查
        ...
+UVM_TESTNAME=new_python_test
修改内容是否重新编译 SV原因
新增用例 / 修改算法 / Python 实例状态不需要用例名称与类在启动时注册
新增受支持 phase 的重载不需要复用已编译的固定回调形状
导入一个新 Python 用例模块不需要在 uvmx_init 发布注册记录前导入
选用尚未编译的自定义 SV 基类需要新增基类桥接注册
修改 SV 可见方法或事务数据契约按契约重新生成 / 编译不是纯 Python 用例逻辑变更
06

已经验证什么，还有什么没做

以下为既有集成验证记录。新的 uvmx_init 入口及标准 new 构造调整已通过本地检查，尚待集成仿真重验。

✓

同一 factory 选择 Python 与原有 SV 用例

对等启动、显式选择、未知名称、名称冲突与错误路径均有回归。

Peer selection
✓

冻结二进制后新增 Python 用例

新增类、新模块导入、新增 phase 与实例状态；编译及生成产物的哈希和文件元数据保持不变。

无重编译
✓

注册数量超过通道容量

1050 个额外声明，发布与消费并行执行，不将用例总数限制在单次通道容量内。

运行时注册
✓

Register Lab 完整场景与 Python super()

Python、SV、Python 扩展用例均运行同一寄存器闭环；新增 Python 子类沿用旧二进制通过验证。

项目集成

当前明确支持

  • 默认 uvm_test 和选定自定义 SV Test 基类
  • 五个同步 phase 回调与 Python 用例继承
  • SvTypes 类型化事务通道
  • 复用公开 CallbackAdapter 的构造、绑定和分发

当前边界 / 后续工作

  • 不是完整 UVM 类库或完整 Python UVM 兼容层
  • 自定义 SV 基类当前要求直接继承 uvm_test
  • Test 构造无用户参数，phase 不传 uvm_phase 对象
  • 更深的组件、factory、sequence 等映射仍需后续扩展
  • 尚未拆分为独立发布的 UVMX 项目

错误边界：构造与 function phase 禁止阻塞；Python 回调异常终止仿真；重复名称不会静默替换已有 SV 用例。此处只说明 UVMX 的固定 Test 接入，不等同于 SVX 通用跨语言继承的全部能力。
